日期：2026-10-12（北京时间）

项目性质：重新开发的独立项目，不沿用旧游戏代码
阶段状态：立项完成；独立仓库已确认可读可写；工程初始化进入第 2 阶段；尚未生成可玩版本

## 1. 已确定的要求与暂定方案

用户确定的要求：横版 2D 肉鸽；按游戏开发常规流程分阶段交付；每阶段有独立文档；代码接入当前绑定的 GitHub 账号；每次发布完整可玩版本都记录修改更新。

本次为启动工作采用以下暂定方案，后续可在进入实现前调整：

- Linux 桌面优先，兼顾 Windows；不默认改成网页游戏。
- 使用 Godot 4 稳定版与 GDScript。具体引擎小版本在工程创建时验证并锁定，开发、测试、导出保持一致。
- 单人横版动作游戏，键鼠操作；一局目标 15–25 分钟。
- 原创废墟幻想题材，采用清晰轮廓、分层场景、连续角色动作与克制特效。美术风格在视觉样板阶段验证。
- 无联网、多人、付费系统；优先把单局战斗与构筑做完整。

暂停、退出、角色与难度选择、五个存档槽、初始安全房、随机障碍、武器与增益／负面效果作为本次建议范围。它们属于暂定设计，不能当作本条用户消息明确指定的全部要求。

## 2. 游戏定位与核心循环

玩家是一名探索失落遗迹的旅者，以近战和远程武器穿越随机组合的房间，在战斗奖励中选择装备与增益，同时承担部分负面效果；击败关底首领完成单局，死亡后保留有限的解锁进度。

完整循环：主菜单 → 选择存档／角色／难度 → 安全房准备 → 战斗房 → 奖励选择 → 事件／休息房 → 首领 → 通关或死亡结算 → 返回菜单。

三项体验支柱：

1. 操作可控：移动、跳跃、攻击、闪避响应及时；受击、命中与危险提示清楚。
2. 构筑能改变打法：武器与增益改变攻击形态、资源消耗或风险，不只增加数值。
3. 画面有生命感：动作过渡、布料／头发摆动、环境细节、分层视差、灯光与音效共同支撑氛围。

## 4. 首个可玩版本的范围

`v0.1.0` 的目标是完整但短小的闭环：

- 一个可操作角色；左右移动、跳跃、近战攻击、闪避。
- 一个安全房和至少两个可通行的战斗房；避免一开始直接落入战斗。
- 至少一种会主动攻击的敌人，玩家与敌人都能受伤、死亡。
- 基础生命值、攻击冷却、命中反馈和危险提示。
- 开始菜单、操作说明、暂停／继续、返回菜单、死亡／通关结算、重开。
- 能从开始走到结算，不依赖开发者调试命令。

该版本不要求五槽存档、多角色、完整随机生成或正式美术。未完成项必须写在发行说明中，不能把原型称作内容完整的正式游戏。

首个版本默认使用简化美术验证操作；第 4 阶段交付正式视觉样板。不能只用颜色变化冒充动作动画或角色区别。

## 5. 技术和资源组织

工程创建后采用以下结构：

```text
project.godot
scenes/             # 菜单、角色、敌人、房间、奖励、结算
scripts/            # 游戏流程、战斗、存档及通用系统
data/               # 武器、角色、奖励、房间等配置
assets/             # 图像、动画、音频、字体及来源记录
tests/              # 核心规则与存档回归验证
tools/              # 构建、版本检查、发布辅助工具
docs/stages/        # 每阶段的独立文档
docs/releases/      # 每个实际发布版本的说明
README.md
CHANGELOG.md
AGENTS.md
```

实现原则：

- 角色、敌人和房间的逻辑分离；不要把整个游戏堆在一个脚本中。
- 武器、奖励与敌人参数优先采用配置驱动；战斗逻辑不散落重复硬编码。
- 随机局保存随机种子、已生成房间、当前房间状态和构筑，继续游戏不重新抽奖励。
- 存档保存格式版本；使用临时文件加替换策略，并保留备份。五个槽独立管理。
- 暂停时冻结战斗计时与伤害，菜单继续响应；避免切回游戏时补算大量伤害。
- 音效、特效、震屏强度可调整，不能遮挡攻击预警。
- 未确认许可的素材不得打包发行；资源来源与许可记录在 `assets/SOURCES.md`。
- 依赖版本固定；正式发布时以实际测试结果描述兼容性，不宣称未测试的平台可用。

## 8. 每次可玩版本的修改更新记录

同时维护：

- `CHANGELOG.md`：按版本汇总新增、调整、修复与破坏性变化；开发中变化放在 `Unreleased`。
- `docs/releases/vX.Y.Z.md`：完整发行说明、操作方式、兼容范围、测试和已知问题。
- GitHub 版本标签与 Release：关联同一提交，提供下载包及 SHA-256 校验值。

发行说明模板：

```markdown
# vX.Y.Z · 版本标题
发布日期：YYYY-MM-DD（北京时间）
源码标签／提交：
构建使用的引擎版本：
已测试平台：

## 新增
- 实际新增的玩法或功能。
## 调整
- 哪项行为怎样变化，为什么变化。
## 修复
- 触发条件、原有问题及修复后的行为。
## 存档与升级
- 是否兼容旧存档；需要迁移时说明方法。
## 运行和操作
- 包名、启动方法、按键及必要环境。
## 验证结果
- 菜单、安全房、战斗、奖励、结算、暂停、重开。
- 存档／继续游戏（本版本若提供）。
- 实际测试设备、平台和性能数据。
## 已知问题与未完成项
- 可复现的问题及影响。
## 下载与校验
- 平台包、下载地址、SHA-256。
```

发布检查顺序：完成代码和文档 → 从干净工作目录构建 → 验证对应版本 → 更新记录 → 提交 → 推送 → 标签 → 上传 Release → 核对标签、提交和发行包一致性。

任一关键检查失败，保留为开发构建；不能用正式版本号掩盖失败。当前没有生成可玩版本，因此尚无游戏发布日志条目。
