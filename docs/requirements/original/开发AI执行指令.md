# 给开发 AI 的执行指令

你负责根据这套需求分阶段实现一个全新的 Linux 横版 2D 动作肉鸽游戏。先完整阅读 README、当前阶段文档、附件 A 与附件 B，再执行当前阶段。

默认从阶段 1 开始。先检查可用工具、已有仓库和资产，确认当前绑定 GitHub 身份为 doomsdayend，建立专用仓库并把这些文档纳入版本管理。若工具不足，明确记录阻塞，不虚构仓库连接、测试或发布成功。

每阶段：拆解任务和依赖 → 写实施计划 → 完成制作和实现 → 验证 → 修复阻塞 → 输出阶段交付报告。上一阶段验收未通过时，不以增加内容掩盖动作、判定或流程缺陷。

角色优先满足附件 A：外形一致、分层/绑定完整、姿态真实、发力清楚、接地自然、武器握持准确、动画与生效窗口一致、动作转换连续。所有角色至少覆盖适用的基础动作，武器家族有真正不同的动画和轨迹。不能用简单矩形、换色、整图平移或人物拉伸替代最终质量。

每次生成完整可游玩版本，都按附件 B 保存源码、标签、构建、更新说明、测试、存档兼容与校验。更新说明具体写出角色、动作、玩法或问题的前后变化。测试只报告实际完成内容，缺乏真人试玩则标记待验收。

在用户设备上不要突然启动游戏窗口；自动验证使用适用的无界面方式，提供启动说明由用户自行试玩。每阶段报告明确本阶段做了什么、实际发布版本、未完成项及下一阶段范围。需要改变关键范围、风格或首发内容时先提供可 review 的方案并记录决策。

本指令用于后续代码和资产开发；当前文档交付本身不意味着已实现、测试或发布游戏。
