# 角色模型与动作动画规范

本附件规定玩家角色、普通敌人、精英与首领的美术和动作质量。“人物模型”在此指 2D 角色设定、分层结构、骨骼绑定或逐帧资产以及运行时动画，不要求建立 3D 模型。最终目标是在实机镜头中具有体积、重量和连续动作的角色。

## 一 造型与比例

默认玩家角色为约 4.5—5.5 头身的风格化手绘人物。选择具体比例后，除明确的动作透视与压缩外不得逐帧改变体型。主角实际镜头站立视觉高度初测约 96—128 逻辑像素，以可读性与场景设计最终冻结；贴图可用更高分辨率，不能把导出像素直接当作物理大小。

每名角色制作：全身标准侧视、前后或三分之四参考、头部表情、手部握持、服装拆层、配色、武器比例、剪影、世界单位标尺。主参考给出头高、肩宽、躯干长、腿长、脚底基线及装备尺寸，避免生成多张图后拼接为不一致的角色。

识别优先顺序：整体剪影 → 武器和体态 → 大色块 → 面部和装饰。角色区别不能只依赖发色；暗背景、灰度与小尺寸也应能认出。

画风统一：轮廓线粗细、亮暗块、边缘清晰度和光源一致。禁止半写实脸搭配简单几何四肢、不同动作服饰忽然增减、手指数量异常、武器穿过手掌。

## 二 分层与绑定

骨骼路线的源文件至少分为头、颈、躯干、骨盆、上臂/前臂/手、大腿/小腿/脚、前后发层、衣摆、披风、武器和特效挂点。左右肢体独立；肘、膝、肩等关节提供遮盖或合理网格变形。

最低挂点：主手、副手、武器柄、刀尖/枪尖、发射口、头部、脚底、躯干受击位置。箭矢、枪弹、法术由挂点发出，不能从角色中心凭空生成。双手武器维持副手接触，单手武器不得由同一姿势假装双手挥动。

绑定交付包含骨骼层级、约束、插槽命名、默认姿势、动画轨道、导出配置。大幅挥砍、透视和表情允许替换绘制帧；禁止使用极端骨骼拉伸近似高质量手绘动作。

逐帧路线须保持统一画布和锚点，每帧有完整轮廓，不裁切头发、武器或特效。空帧、重复停帧可按时序有意使用，但不能为了凑帧数重复贴同一张静态人物。

## 三 动作清单与预算

下表为基础生产目标。逐帧数量是建议的独立绘制姿势预算；骨骼动画以时序和关键姿势验收，不要求机械对应相同绘制数量。运行帧率、骨骼采样率与绘制帧率是三件事。

| 动作 | 建议姿势/关键帧 | 动作内容与时序要求 |
| --- | --- | --- |
| 待机 | 8—12 | 呼吸、重心和衣摆轻动，脚底不漂移；约 1.2—2 秒循环 |
| 起步 | 3—5 | 重心前移、蹬地，快速进入跑步 |
| 跑步 | 8—12 | 接地、下沉、蹬伸、腾空，左右交替；步频随速度变化 |
| 急停 | 3—5 | 身体惯性与衣摆延迟，不能滑行数个身位 |
| 地面转向 | 3—5 或短混合 | 体态回转与武器归位；不阻塞方向响应 |
| 起跳 | 3—5 | 下压和蹬伸；预备不得延迟即时跳跃响应 |
| 上升 | 2—4 | 重心伸展、腿部收起、衣发滞后 |
| 最高点 | 2—3 | 轻微悬停姿态，不能暂停物理模拟 |
| 下落 | 3—5 | 身体及衣物随速度变化，预备接地 |
| 轻落地 | 3—5 | 膝盖缓冲，短过渡，支持输入缓冲 |
| 重落地 | 5—7 | 更大下沉和回弹；若有硬直须明确条件 |
| 闪避/翻滚 | 6—10 | 预备、位移、恢复；无敌与视觉事件对齐 |
| 地面攻击第 1/2/3 段 | 每段 6—10 | 独立蓄势、挥动、命中与收势，方向和重量逐段变化 |
| 空中攻击 | 6—10 | 与地面动作不同的重心、腿部姿态与轨迹 |
| 重击或蓄力 | 8—14 | 蓄力阶段可循环，释放及收势独立 |
| 独有技能 | 8—16 | 预备、生效、持续/移动、结束，动作揭示能力用途 |
| 轻受击 | 3—5 | 短反应，方向来自伤害源，角色可迅速恢复 |
| 重受击/击倒 | 6—10 | 后仰或击飞、落地，按规则进入起身 |
| 起身 | 5—8 | 支撑、恢复重心，有明示保护规则 |
| 死亡 | 8—12 | 受击失衡、倒地、停止；不只是透明渐隐 |
| 交互/拾取 | 4—6 | 可中断的触碰或拾取，避免战斗中强制长演出 |
| 出生/传送 | 6—10 | 出场结束后交还控制，位置与碰撞安全 |
| 胜利/选择展示 | 8—12 | 角色个性动作，不影响实战动作预算 |

正式版每名玩家角色至少覆盖上表适用动作。空中转向通过朝向和姿态响应完成，不必强制新增一段耗时动画。若不设计击倒系统，可合并重受击与起身，但须记录行为和动画如何覆盖，而非留下缺省动作。

普通敌人最低清单：待机、移动、察觉/瞄准、每个招式的预备/生效/恢复、受击和死亡；飞行、盾兵、召唤者增加对应专属动作。首领每个招式独立制作，并增加登场、阶段切换、失衡或暴露窗口和死亡。

## 四 关键姿势与发力

挥砍应能看到蹬地、髋转、躯干带肩、手臂随动、武器到达、惯性收势。突刺体现身体前压与手臂延伸；弓体现抬弓、拉弦、蓄力、放弦和回位；符铳体现举枪、瞄准、击发和后坐；施法体现聚能、引导、释放和收束。

重武器比轻武器有更强预备、较大身体位移和更长恢复，但控制响应不能拖沓。空中攻击保留腾空重心，脚不能像站地面一样持续踩住隐形平面。

跑步接地脚在接地段尽量保持世界位置，按速度调步频而非横向滑动；落地先腿和骨盆吸收力量，再由上身与衣物跟进。

## 五 动画和玩法时序契约

每个攻击有唯一动作 ID，配置总时长、预备段、生效段、恢复段、命中事件、允许转向段、位移曲线、连击窗口、取消窗口、被打断规则和攻击实例 ID。

示例设计初值：轻刃第一击 0—70ms 预备，70—130ms 生效，130—300ms 收势；可在 150—270ms 接收下一段连击，150ms 后允许闪避取消。时间必须与实际动作、移动及角色平衡一起调整。不能把这个示例直接套给全部武器。

伤害生效须和武器轨迹、弹丸出生或法术区域形成一致。禁止全动画期间开启攻击框。多段技能每一段有明确命中计数规则；命中停顿不重复触发动画事件。

攻速变化按分段规则缩放；需要保留最低预备与恢复以保证可读性。定格、暂停、失焦、慢动作和低帧率都应保持事件只触发规定次数。导出后须再验证，不只在动画编辑器里检查。

## 六 状态、取消与打断

核心状态包括：待机、移动、起跳/上升/最高点/下降/落地、闪避、攻击、技能、受击、击倒/起身、死亡、交互和传送。

| 当前状态 | 可执行操作 | 限制 |
| --- | --- | --- |
| 待机/移动 | 跳跃、攻击、闪避、技能、交互 | 根据资源和接触条件 |
| 上升/下降 | 空中攻击、允许的空中技能/闪避、转向 | 空中次数与资源上限明确 |
| 攻击预备/生效 | 缓冲下一段，特定允许段转向 | 不默认全段取消 |
| 攻击收势 | 连击、闪避，部分技能 | 按武器窗口执行 |
| 闪避 | 朝向响应及动作缓冲 | 位移中不任意叠加攻击 |
| 受击/击倒 | 按规则恢复 | 输入不瞬间消除硬直 |
| 交互 | 移动或闪避中断 | 不丢失领取事务 |
| 死亡 | 结算/返回标题 | 不接受战斗指令 |

优先级默认死亡最高；受击是否打断取决于霸体、无敌和伤害规则；剩余技能、攻击、移动由明确窗口决定。暂停是系统状态，不参与角色动作竞争。禁止把“新输入直接替换当前动画”作为所有状态规则。

## 七 朝向、武器与装备

左右翻转需以统一脚底/骨盆锚点进行，防止转向时跳位。非对称披风、佩饰、护手或文字纹样视美术要求制作左右版本或单独处理，不能让关键设定因镜像错乱。

武器视觉尺寸不改变角色实体碰撞。短刃、重剑、长枪、弓、符铳、法器有各自握持姿势和发射/挥击挂点；持武器待机、跑步、跳跃至少通过叠加或专用姿态正确覆盖。

默认护甲和饰品先采用图标及特效反馈，不承诺每件装备都改变完整服装；若制作可视装备，则每件必须通过全部动作兼容测试。新皮肤保持玩法碰撞和时窗，避免外观带来额外命中优势。

## 八 判定和尺寸

站立实体碰撞以固定 H 和宽度定义；角色全身视觉边缘不自动当作受击区。脚底基线、武器插槽和受击框使用引擎坐标记录，导出裁切或透明边界变化不能移动锚点。

受击框可按闪避、倒地等状态调整，但规则可见并与无敌分开；攻击框随轨迹或独立形状控制。大披风、长发与纯视觉特效不扩大受击范围。

翻滚期间若改变实体尺寸，需测试墙角和低顶恢复，不能恢复站立时嵌入墙体。坡面、台阶、快速落地及镜像都检查接地与判定。

## 九 输出文件和登记

命名建议：角色ID_动作ID_武器族_方向_资产版本。骨骼资产交付源文件、纹理、骨骼/动画数据与工具版本；逐帧交付源文件、透明 PNG 或图集与帧序/时长/锚点元数据。项目规格选择其一，不强制把骨骼动画再转成巨大逐帧图集。

发布纹理使用透明背景，无绿边、白边、裁切和渗色；图集留足边缘扩展，过滤设置按实际缩放验证。源资产备份与版本记录不可遗漏。

登记字段：资产 ID、所属角色、动作、武器、方向、尺寸/世界尺度、锚点、时长、帧或轨道数量、事件时刻、循环/打断规则、作者或来源、授权、源文件、导出文件、预览、审核结论及关联提交。

## 十 验收方法

1. 对照角色参考检查全部动作的头、手、服装、配色和武器身份一致。
2. 实机 1 倍画面观察剪影、脚底、发力、预警与动作可读性；再用慢放检查事件和命中框。
3. 快速切换跑、跳、攻击、闪避、受击，覆盖左右朝向、地面/空中、30/60/120 FPS。
4. 执行 100 次动作转换抽测，无卡姿势、脚漂移、插槽跳动、事件重复或永久失控。
5. 检查角色和全部武器家族组合；共享动画可按基础骨架测试再抽测每件视觉资产，不能省略差异显著的长枪和双手武器。
6. 用灰度、暗场和多特效场景检查敌我可读性；关闭特效后动作仍然能表达攻击。
7. 动画表现、玩法判定、技术稳定、来源授权四项分别判定。任一阻塞未通过，就不能把该资产标为正式完成。

审核结果必须有具体证据和待修列表。最终玩家角色不允许以“后续补动作”为由发布缺失的基础动画。
