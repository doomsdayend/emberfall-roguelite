# 阶段 1 立项与预制作

目标：在投入程序和批量美术前，确定游戏要做成什么、最小验证范围是什么，以及怎样判断完成。此阶段产出方案与设计资产，不发布可游玩版本。

## 进入条件

已经阅读总需求；识别本次是全新项目，不默认继承旧项目架构或角色资产。允许借鉴过去的经验，但任何复用都须记录来源和适配工作。

## 产品设计

形成简明 GDD，至少覆盖：体验目标、玩家画像、控制方式、核心循环、失败与永久成长、角色差异、战斗距离、地图结构、武器、增益与代价、难度、存档、界面、内容数量、交付平台。

核心循环固定为：选择存档 → 选择角色和难度 → 安全初始房间 → 选择起始武器 → 探索战斗和构筑 → 首领 → 区域推进 → 胜利或死亡结算 → 永久解锁 → 再次出发。首局不能直接进入怪物围攻。

正式版优先级：

| 等级 | 范围 | 处理方式 |
| --- | --- | --- |
| 必须 | 流畅移动、战斗、角色动画、3 区域主线、存档、暂停退出、可安装发布 | 发布缺失即不通过 |
| 应有 | 手柄、设置、图鉴、训练场、帮助与可读性选项 | 正式版前完成，裁剪必须修订需求 |
| 延后 | 联机、创意工坊、复杂剧情演出、每日在线挑战、无限关卡 | 不进入首发关键路径 |

## 角色和美术预制作

先完成主角“烬刃”的侧视标准模型、比例标尺、前后或三分之四参考、表情、配色和武器尺寸。动作概念至少画出待机、跑步接地、起跳、最高点、落地、攻击预备、命中、收势、翻滚、受击、死亡的关键姿势。

同屏给出主角、近战敌人、远程敌人与大型首领的剪影比较。以 1280×720 实际游戏视角验收，不能只展示放大的立绘。

环境概念展示三个区域的色彩、材质、光源、前中后景层次和可交互物的识别方式。界面必须与环境风格统一；战斗区不能被复杂背景和装饰遮挡。

## 技术和资源路线

- 比较引擎的 Linux 导出、资产导入、动画事件、工具维护、授权成本和构建自动化，选定具体版本并记录理由。不是默认追求最新版。
- 选定角色动画路线：骨骼为基础，手绘逐帧补充攻击、表情和特效；若纯逐帧质量与成本更合适，可采用纯逐帧，但所有动作验收不降级。
- 明确最小设备档位并记录 CPU、GPU、RAM、分辨率、驱动。60 FPS 目标绑定具体测试机，未测量不得宣称支持任意 Linux 设备。
- 原生基准画面 1280×720；适配 1920×1080 和常见宽高比，镜头有效视野不能因比例扩大而破坏战斗设计。
- 世界尺度：主角站立碰撞高度定义为 1H。移动和场景距离以 H 或引擎单位描述，贴图像素不直接决定物理尺寸。
- 列出模块边界：输入、角色控制、战斗结算、动画、敌人 AI、地图生成、物品构筑、存档、UI、音频、构建。
- 设计数据表字段、存档 schema、资产命名、版本记录和异常日志策略，具体实现留到后续阶段。

## GitHub 初始化要求

读取当前连接身份，确认 `doomsdayend`；创建或选择属于该账号的专用新仓库，不覆盖旧项目。初始化 README、docs、任务清单、资产授权记录、CHANGELOG 和忽略规则；动画源文件等大二进制采用适用的大文件管理方案。权限、工具不可用时明确记录未连接，不伪造成功。

## 交付与验收

交付：GDD、项目范围清单、技术决策、首批角色设定、环境概念、动作清单、风险登记、仓库信息和阶段 2 任务列表。

通过条件：核心循环明确；每个首发需求有阶段和验收方法；主角关键姿势与尺寸统一；引擎和动画工具可完成一次最小资产导入及 Linux 导出验证；仓库账号和路径有真实核验；成本、性能与资产来源风险有处理方案。

禁止在范围和美术标准仍模糊时批量生成数百素材。若一阶段无法解决技术导出或角色动画路线，先解决阻塞，不能以“后续完善”进入内容量产。
