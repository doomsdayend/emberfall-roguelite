# GitHub 与版本发布规范

目的：后续游戏代码接入当前已绑定 GitHub 账号，每一次可游玩版本都记录做了什么、如何验证、如何下载与恢复。

## 账号和仓库

本次通过当前 GitHub 连接只读核验，登录名为 `doomsdayend`。执行开发时再次读取连接身份，不能凭历史用户名代替当前身份。暂定专用私有仓库 `doomsdayend/emberbound-2d-roguelite`，未创建、未检查名称可用性；重名时采用明确后缀并记录实际 URL。

权限不足或没有仓库创建能力时，应说明阻塞和具体所需操作；不要更换账号、暴露 Token 或把内容写到现有不相关仓库。若有多个绑定身份且当前身份无法确定，再由用户选择。

仓库从阶段 1 开始保存需求与设计，后续加入项目源码和资源。工作目录建议包括 docs、assets/source、assets/exported、game、tests、tools 和 releases 的说明/元数据。实际目录按引擎调整，不把发布二进制长期提交到普通 Git 历史；使用 Release 附件，大源文件按方案管理。

## 提交与开发记录

默认 main 保持最近一次通过验证的状态，阶段工作用独立分支，通过 PR 或明确评审后合入。提交按可理解的功能单元组织，描述改变及原因；不要每次直接堆成“update”。

每阶段任务关联需求 ID，每次 PR 说明：触发问题、最终行为、主要修改、实际运行测试、存档影响和遗留风险。架构、范围、角色风格和生成算法改变须追加决策记录。

建议需求 ID：SYS 系统、ACT 动作、ART 美术、COM 战斗、MAP 地图、ROG 构筑、SAV 存档、REL 发布；需求表记录阶段、优先级、验收与证据位置。

## 发布对象和版本

每个完整可游玩构建，不论原型、Alpha、Beta、RC 或正式版，都必须具有唯一版本。开发中可玩版本使用 v0.x.y；正式版之后用 v1.x.y。Alpha/Beta/RC 在标题和 Release 中清楚标记，必要时使用预发布标识。

标签固定到通过验证的源码 SHA；不能移动旧标签。补发修复使用新版本。失败发布不能写为成功，未上传附件的 Release 不能算完成发布。

## 每次发布步骤

1. 冻结版本范围，关闭 P0/P1 或按早期原型门槛明确限制；确认该版本可玩流程。
2. 在候选提交构建目标平台包，记录引擎和依赖版本、构建配置与时间。
3. 对同一个候选包完成干净环境启动、主流程、关键动作、存档与暂停回归。
4. 填写更新说明和测试报告，更新 CHANGELOG、兼容表和资产来源；保留实际证据。
5. 以最终文档和源码提交重新构建，至少重跑安装启动与变化范围，记录最终 SHA 和文件校验值。
6. 给最终 SHA 创建版本标签与 GitHub Release，附构建、源码入口、更新说明和 SHA-256。
7. 核验 Release 页面、版本、附件和 SHA 对应，下载附件检查大小与校验值；必要时再次启动发布附件。
8. 在发布台账登记真实链接和结果。不凭“上传命令已提交”宣布成功。

流程可以由 CI 自动完成，但没有自动化能力时仍需手动遵守。文档不假设当前环境已经具备创建仓库、标签或 Release 的工具。

## 必须保存的记录

- CHANGELOG.md：按版本列新增、调整、修复、美术动作、性能、存档变化和已知问题，链接详细发布说明。
- docs/releases/<版本>.md：具体修改前后行为、角色动作清单、测试条件、源码 SHA、包名和校验值。
- docs/testing/<版本>.md：测试环境、用例、预期与实际结果、复现种子、人工验证和未覆盖项。
- docs/decisions/：架构、美术标准、范围、存档和算法的关键决策。
- 发布台账：版本、日期与时区、范围、源码 SHA、Tag、Release、附件、兼容、测试结论、回滚版本。

更新记录不能只有“修了一些 Bug”。例如：“烬刃第三击在收势中接闪避会丢失输入；现允许指定窗口缓冲，补充恢复姿态；30/60/120 FPS 下左右转向均验证”。仅记录真实完成的修改。

## 安全与授权

不提交密钥、Token、个人凭据、系统缓存和未授权素材；使用环境或平台凭据机制。公开仓库和公开发布必须有用户授权，默认私有不能擅自改为公开。发布资产仅包含运行需要的合法内容，编辑源文件按许可证和仓库权限管理。

## 兼容与回滚

每版本注明存档 schema、可从哪些旧版本迁移、活动局是否可恢复和备份位置。保留旧构建与标签。发现问题时标记撤回并发布新修正版；不覆写同版本附件隐瞒差异。回滚需验证旧版能否读取现有档，不能用源码回退代替用户数据恢复。

## 完成判定

真实仓库身份已核验、源码可取得、标签唯一、目标包可下载并游玩、更新说明完整、测试可追溯、存档影响已说明，全部成立才算“该版本已发布”。本次文档包未执行上述仓库写入和游戏发布动作。
