# 横版 2D 动作肉鸽游戏分阶段需求文档

文档版本：1.0 ｜编写日期：2026-10-12 ｜状态：可用于新项目立项与分阶段开发。

本项目从零建立新的横版 2D 动作肉鸽游戏。核心体验是动作连贯、攻击有力度、角色有鲜明外形与完整动画、随机构筑能改变操作方式。本文档包只规定需求、交付物和验收条件，不包含游戏代码，也不代表仓库或游戏版本已经创建。

## 默认方案与范围

- 目标平台：Ubuntu 24.04 x86_64 桌面；首发不要求 Windows、移动端、浏览器或联机。
- 类型：横版视角、单人、房间式探索与战斗，平台跳跃作为空间战斗辅助手段。
- 暂定题材：原创幻想世界中的余烬遗迹。名称与世界观可在阶段 1 调整，禁止直接使用商业游戏角色、地图或音频。
- 美术：精致手绘 2D 角色，骨骼动画结合局部逐帧动画；动态光影、景深分层和环境动画。不是默认像素风，也不以几何图形换色作为最终角色。
- 控制：键盘鼠标与手柄；第一版就有暂停、返回标题、失败与重新开始。
- 正式版目标：3 名角色、6 个武器家族、3 个区域、3 名首领、普通与精英敌人、正面增益和可选择的负面代价、5 个存档槽位。
- 正式版单局目标 25—40 分钟。此时长、动作时间与数量是设计初值，实际平衡需通过试玩收敛。
- 引擎和具体动画工具在阶段 1 冻结，须支持 Linux 导出、状态机、2D 骨骼或精灵动画、数据驱动和可复现构建。可评估 Godot、Unity 或其他合适方案；不因未选引擎阻止文档使用。

以上是本需求采用的默认设计，不是用户已确认的引擎、美术成品或最终设备性能。阶段 1 必须把调整后的结果写入决策记录，避免中途无记录换方向。

## 全程必须遵守

1. 每阶段先读该阶段文档、总需求、角色动作规范和发布规范；只推进已通过依赖验收的内容。
2. 每个可游玩版本必须在干净目标环境安装启动，从标题进入并完成该版本声明的流程；原型不要求拥有正式版全部内容。
3. 角色造型、姿势与行为动画必须形成一致体系；同一动作不能靠拉伸人物、整张图片平移或只更换特效来冒充。
4. 每次发布都有可下载构建、源码提交、Git 标签、更新说明、测试报告、已知问题、存档兼容说明和 SHA-256。
5. 使用当前已绑定 GitHub 账号 `doomsdayend`。暂定新仓库名 `emberbound-2d-roguelite`，该名称未检查占用、仓库尚未创建。默认私有；若环境不能创建或账号不符，记录阻塞并请求用户解决，不冒用其他身份或在无关旧仓库写入。
6. 本次不创建仓库、不推送代码、不发布游戏；GitHub 连接与持续记录是后续开发执行要求。
7. 最终美术资产须有制作源文件、导出文件、许可证或原创说明。不得把其他游戏截图拆成素材。
8. 用户设备上不得自动弹出游戏窗口。自动验证用适用的无界面方式；需要人工窗口试玩时由用户自行启动。
